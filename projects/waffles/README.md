# Waffles

Mike Gashler's machine learning and data mining library: neural networks, decision trees, k-nearest neighbours, manifold learning, recommender systems, clustering and more, with command-line tools that use them. It is public domain.

It comes from [mikegashler/waffles](https://github.com/mikegashler/waffles). This copy was imported in February 2023 and matches upstream commit `f0cfa46` (2023-01-05). Upstream has had one commit since, `d6b734b` (2023-11-29); its two fixes were taken (see below) and the rest, which stubs out part of `WJsonAsADatabase`, was not. SAKBox maintains this copy from here.

## Building

| Target | What it is |
| --- | --- |
| `//projects/waffles:WClasses` | The library. Include `<WClasses/...>`; the namespace is `WClasses`. |
| `:learn`, `:cluster`, `:dimred`, `:generate`, `:plot`, `:recommend`, `:sparse`, `:transform`, `:audio`, `:wizard` | The command-line tools (`:generate`, `waffles_generate`, makes datasets; its source is in `src/depends/generate/` because it needs libpng) |
| `:WImagePng` | PNG reading and writing for `WImage`s (`<png/WImagePng.h>`), on the repo's libpng. Separate from `WClasses` so only programs that use PNGs need libpng. |
| `:Gui` | An SDL front end for Waffles' widgets (`<gui/Gui.h>`: views, controllers and file and message dialogs), used by the GUI demos |
| `//projects/waffles/demos/...` | Demos built with Bazel: `chess`, `caronhill`, `community` (a multi-user forum and recommender, served on port 8988 to the network, keeping its data in `WJsonAsADatabase` files), `eigen`, `hello_gui`, `hello_ml` (several learners predicting a pizza's taste and price), `interpolate` (pick a learner and watch it fill in a small picture as a big one, from each pixel's position), `paint` (a paint program that opens PNGs and JPEGs and saves PNGs; it opens and saves files in the folder you run `bazel run` from), `fourier_net` (the Fourier-initialised network from arXiv:1405.2262, trained on a NASDAQ series; `bazel run //projects/waffles/demos/fourier_net -- --epochs 5`, or no `--epochs` to run until stopped; it writes `fourier.svg` and `progress.svg` where it is run), `time_series` (a simpler network of the same kind, of sine, softplus and identity units, on another series; `-- --epochs N`, 50,000 by default; it draws `progress.svg` where it is run), `neural_nets` (fully connected, convolutional and autoencoder networks on 35 MNIST digits; about two minutes), `raytrace` (renders the RenderMan scenes in its `bin/`, picked in a file browser), `hello_console`, `hello_web` (a page served on port 8989, opened in your browser), `qlearning` (a Q-learning agent in a small world, in the terminal) and `diff` (`-- FILE1 FILE2` shows the two side by side in your browser, then exits) and `jumper` (a robot, simulated by the repo's Cyclone engine, that learns to jump: `-- train` evolves policies, saving `policy<N>.json` where it is run; `-- policy250.json` shows one jumping in a window, R to jump again; `-- height [FILE]` prints how high a policy jumps, or the hand-made one; `-- manual` shows the hand-made one). `series_networks` holds what `fourier_net` and `time_series` share: `:LinearWeights` (identity, perturbation, regularization and input renormalization for a `WBlockLinear`'s weights, as the old `WLayerClassic` had) and `:SeriesPlot` (draws a network's curve over a series as an SVG). `cuda` (needs CUDA) isn't built. |
| `:test` | Waffles' own test suite, including its command-line tool tests (the tools are its data deps). It fails if any test fails or, under `bazel test`, if the tools can't be run. |
| `:WApp_test`, `:WCluster_test`, `:WMatrix_test`, ... | SAKBox's tests, one per area of the library (see Tests below); `:WImagePng_test` tests `:WImagePng` |

`waffles_wizard` and `waffles_plot graph` serve their pages to your browser at `http://localhost:8421`. Only this computer can connect, and they say so when they start. To let other devices on your network use them too, run `waffles_wizard -network` or `waffles_plot graph -network`; anyone on the network can then connect, as they warn. (In code, `WHttpServer`, `WDynamicPageServer`, `WTCPServer` and `WPackageServer` take a `networkAccessible` argument, false by default; the `community`, `diff`, `hello_web` and `security` demos, which are meant to be reached from other machines, pass true.)

A server runs with `WHttpServer::serveRequests()`: it handles requests until `stopServing()` is called (from a request handler, `onIdle` or another thread) or the program gets SIGINT or SIGTERM; SIGPIPE, a browser hanging up, doesn't stop it. Between requests it calls the virtual `onIdle(secondsSinceLastRequest)`, where a server puts its own policy: `waffles_plot` stops after 30 idle minutes, the wizard after 15, `diff` 8 seconds after the browser's last request, and `community` does its maintenance every four hours. This is upstream's `WDynamicPageServer::go()` brought back into the library. Until 2019, `go()` ran the loop, did maintenance every four hours by calling the hook `onEverySixHours()` (misnamed), and called `onShutDown()` when it ended; `shutDown()` stopped it, and `onStateChange()` was a hook nothing ever called. Upstream's commit 9628b7f (2019) removed `go()`, its flag and the hooks from the library (and `doMaintenance()`'s body, leaving its declaration) without updating the programs: `community` copied the loop into its `main`, plot and the wizard into their own `pump()`s, all keeping empty hooks that nothing called, and `hello_web` still called `go()`, so it didn't build. `go()` also stopped on any signal, SIGPIPE included. Now each program's policy is an `onIdle` override, `stopServing()` is the old `shutDown()`, a shutdown step is code after `serveRequests()` returns, and the dead hooks and declaration are gone. `WHttp_test` covers the loop.

`WSignalHandler` (used by `serveRequests`) catches SIGINT, SIGTERM and SIGPIPE. It used to catch SIGSEGV as well, but returning from a segfault's handler re-runs the faulting instruction, so a crashing server spun at full CPU forever instead of ending; a segfault now ends the program as usual (`WApp_test`).

ARFF `string` columns load as categories: each distinct text (compared exactly, ignoring surrounding quotes) is one value, so a column of names or labels is usable by any learner. Waffles stores values as numbers and has nowhere to keep text, and upstream loaded these columns as zeros, discarding the text. A column where most values differ (at least 20, in more than half the rows) is likely free text, which a learner would see as arbitrary numbers, so loading it prints a warning. Saving writes the column as a category (`{alice,bob,...}`), not `string`. To refuse such files instead, for when nothing should be loaded that Waffles can't represent as written, pass `WArffStrings::refuse` (`m.loadArff("data.arff", WArffStrings::refuse)`, and the same for `parseArff`): loading throws, naming the first string column, and the matrix keeps what it held. The default, `WArffStrings::asCategories`, is the behaviour described above.

It builds with the rest of the repo as strict C++26 with `-Werror`. Bazel is its only build: upstream's Makefiles, CMake files and Visual Studio projects are removed. The `cuda` demo is kept but not built (it needs NVIDIA's CUDA toolkit, and its Makefile was its only build).

## What SAKBox has changed

- **Names: `G` became `W`.** Upstream names everything with a `G` prefix, for Gashler (`GMatrix`, `GVec`, the `GClasses` namespace). SAKBox uses `W`, for Waffles, to match the library's name and its `src/WClasses` folder, and so the names aren't taken for Google's. Every class, typedef, helper function (`WApp_ParseArgs`), macro (`WAssert`), header guard and file Waffles declares was renamed, and `GClasses` is `WClasses`. To compare with upstream or port from it, swap the prefix: a name that is `G` followed by a capital letter or digit is the same name with `W` here. Names that aren't Waffles' keep their `G`: those of the third-party code it bundles (DirectInput's `GUID_...`), OpenGL's, the GIF file signature `GIF89a`, and the web server's session cookie `GDPSI`. Upstream's release history (`web/docs/changelog.html`) keeps the names as they were released.
  - Saved files name their classes (`"class": "WDecisionTree"`). Files saved with the old names still load: `WDomNode::getClassName` reads a `G` prefix as `W`, and every loader compares against it. New files have the `W` names, which upstream Waffles can't load.
  - The files were moved in a commit of their own, so `git log --follow` traces each back through the rename. The commits that renamed the names are in `.git-blame-ignore-revs`, so `git blame` looks past them (see the top-level README's [git blame past mechanical changes](../../README.md#git-blame-past-mechanical-changes)).
- **Stemming:** `WStemmer` uses the repo's libstemmer (Snowball's `porter`, the Porter algorithm as published) instead of a copy of Martin Porter's own C version, which departs from the published algorithm in a few places. So a few words stem differently, about 1 in 220 of a dictionary: "-ology" words ("biology" is now "biologi", was "biolog"), "-ibly" and "-ably" words ("accessibly" is "accessibli", was "access") and two-letter words ("as" is "a"). A vocabulary saved with the old stems won't match those words. Words of any length are stemmed whole (the old code cut them to 63 letters). `WStemmer_test` covers the stems; the new `WStemmer` was also checked against libstemmer on all 235,976 words of `/usr/share/dict/words`.
- **jumper: on Cyclone instead of Bullet.** Upstream simulated the robot with a copy of Bullet 2.77 (`demos/bullet-2.77`) and showed it with Bullet's GLUT demo framework. It now runs on the repo's Cyclone engine (`projects/cyclone`), and Bullet is no longer a dependency of the repo. Cyclone gained what the robot needs, following Millington's book where it covers them (see Cyclone's README, [Hinges and cones](../cyclone/README.md#hinges-and-cones) and [Capsules](../cyclone/README.md#capsules)): capsules, hinges with limits and motors, and a neck that tilts up to 45 degrees. `Robot` (`src/Robot.h`) is Bullet's `RagdollDemo` robot, with the same parts, sizes, masses, joint limits and motor strengths (Bullet's motor impulse per 1/60 s step is a torque of 60 times it); its parts start with each joint's anchors together, where Bullet's started up to 10 cm apart, and its feet grip with the book's rubber on concrete (0.9, appendix B). `Jumper` (`src/PolicyLearner.h`) is the robot moved by a policy: before each physics step the policy reads the time and how the robot is lying, and sets the motors. Training scores a policy and the window shows it the same way, in steps of 1/60 s, each in two sub-steps (the Cyclone demos' `FixedSteps`), so a policy jumps in the window exactly as high as it scored. The window is the Cyclone demos' (`RigidBodyApplication`, opened with `runInWindow`): R jumps again, `[` and `]` change the sub-steps, `--keys` plays input into it. The hand-made policy jumps 0.47 m (0.63 m on Bullet); policies trained on Bullet don't carry over. Its policy network, written for the 2015 layer API, is a `WNeuralNetLearner` of `WBlockLinear` and `WBlockBentIdentity` (the old "bend" activation: the same formula), and the evolutionary search works on the network's weight vector. `PolicyLearner_test` runs the simulation without a window: the hand-made policy's jump (exactly the same every run, and to the last bit on every platform, since Cyclone's maths is correctly rounded and the build turns fused multiply-adds off), the robot slumping with its motors off and staying within its joints' limits, saving and loading a policy, and a short training run.
- **More demos built:** `neural_nets` and `time_series` were written for the 2015 layer API (`WLayerClassic`, `WActivation*`), removed upstream without updating them; they now build their networks from blocks, `time_series` as `fourier_net` was ported (it no longer opens Firefox, and the old x86-64 build of it in its `bin/` is gone). `neural_nets` trains with `WNeuralNetLearner`'s own SGD, so its learning rate and momentum are the defaults; its convolution uses 5x5 filters (4x4 before); its autoencoder trains on pixels scaled to 0..1 (tanh can't output 255, so nearly every pixel used to count as missed); and its R-Prop and dropout examples, already switched off, are gone with the methods they called. `raytrace` uses the shared `:Gui`, and its RIB parser is a library, `:WRibParser`, on the current mesh API; a number in a scene that isn't one is an error rather than 0, and two lookups no longer return a reference to null (`WRibParser_test` renders the three sample scenes). `hello_web` finds its files in the runfiles and serves the style sheet its page links to (it answered 404). `chess` no longer prints its runfiles tree when it starts (a leftover debugging aid).
- **Gui windows and popups:** a view names its window (`ViewBase("Chess")`); the title was "Car On Hill" for every demo. Popups (`RunPopup`: message boxes and the file dialogs) didn't work after the move to SDL2: each view made its own renderer, which SDL refuses for a window that already has one, so a popup drew nothing, and each view destroyed the shared window when it closed, so closing a popup took the program's window with it. Views now share one window, renderer and texture, and the last to close destroys them; a popup keeps the window's title. The dimmed copy of the screen behind a popup had its colour channels shuffled (`captureScreen` copied the texture's BGRA pixels into a `WImage` unconverted, and didn't unlock the texture); pixels now convert with `std::byteswap` both ways, which also mends `blitImage`'s non-Apple branch (it didn't compile).
- **Demos on the shared libraries:** `interpolate` and `paint` carried their own copies of `Gui` and `WImagePng`, from before `Gui` moved to SDL2, so they no longer built, and their `WImagePng`, saving a PNG without alpha, wrote every pixel in the colour of the first. They now use `:Gui` and `:WImagePng` (and `paint` the repo's libjpeg-turbo for its own `WImageJpeg`), with their views drawing into `Gui`'s SDL2 texture. `interpolate` was written against an older Waffles, from before activation functions became blocks: it no longer includes `WActivation.h`, and its network for the display is copied with `copyTopology` and `init` and given the trained weights each frame (weights now belong to the network, not its optimizer); `WNeuralNet_test` checks the copy has its own weights. `paint` lost `EvalRS`, which nothing called (it also freed `new[]` arrays with `delete`), and its equalise button does nothing until its box holds a number (it read text as 0).
- **Layout:** the library folder `src/GClasses` is `src/WClasses`, and includes use `<WClasses/...>` rather than relative paths. `waffles_generate` builds with Bazel against the repo's libpng and zlib (`:WImagePng`), so its own copies of libpng's and zlib's headers and of `WImagePng` are gone; its `sprintf`s became `snprintf`, a long `-pre` or `-suf` in `imagestoarff` now gives an error instead of overflowing the file-name buffer, and `scenerobotsimulationgrid` and `scenerobotsimulationpath` work out the widest view in `double` (an integer division cut it to whole pixels, while the frames it was compared with weren't). Platform checks use `__APPLE__` instead of a `DARWIN` define.
- **`WRand` is a standard random bit generator:** it has `result_type`, `min()`, `max()` and `operator()` (which calls `next()`), so a `WRand`, or a subclass such as `WRandMersenneTwister`, can be passed straight to the `<random>` distributions, `std::shuffle`, `std::sample` and anything else that takes one; `WRand.cpp` checks `std::uniform_random_bit_generator` at compile time. It isn't a full random number engine (it can't be copied, compared or streamed), so the engine adaptors such as `std::discard_block_engine` can't hold one. The standard leaves `std::shuffle`'s and the distributions' algorithms to each library, so the same seed gives different results on different platforms; where exact results matter, as in Waffles' learners and tests, use `WRand`'s own methods (`shuffle`, `uniform`, `normal`, ...), which are the same everywhere. Tested in `WRand_test`.
- **Modern C++:** `std::random_shuffle` (removed in C++17) became a Fisher-Yates shuffle with the learner's own seeded `WRand`, `sprintf` became `snprintf`, missing `override`s were added, an exception is caught by reference, and `WMasterThread`'s worker count is `std::atomic` rather than `volatile` (it is read without the lock). Classes that mustn't be copied (`Holder`, `ArrayHolder`, `WVec`) say so with `= delete`, instead of private copy functions that threw if reached (`WVecWrapper`, a friend of `WVec`, could reach them); `WVec` has a move constructor, so `a + b` returns by value without relying on the compiler skipping a copy; and `W3DVector` uses the compiler's own copy, so it is trivially copyable. A `WVecWrapper` copy wraps the same memory; assigning one is not allowed (`setData` or `copy` says which is meant). A filter's `prefilterFeatures` and `prefilterLabels` can return their input itself, so passing a temporary (`f.prefilterFeatures(a + b)`) is a compile error: `WFilter` declares both, beside deleted `&&` overloads, and does the pass-through itself; a filter implements the protected `transformedFeatures` and `transformedLabels` instead, returning its result or `nullptr` for "unchanged". So a new filter can't hide the deleted overloads or return its parameter.
- **Security** (upstream): Waffles' web server, used by `waffles_wizard` and `waffles_plot graph`, accepted connections from the whole network, and one bad header could overflow its memory: `Content-Length: -1` gave a zero-byte buffer that the request body was written into, and over-long URLs, parameters, cookies and `If-Modified-Since` dates were copied into fixed buffers unchecked. It now listens on this computer only unless asked (above), reads `Content-Length` strictly (up to 64 MB), and hangs up on, and logs, any request that doesn't fit. The HTTP client reads a reply's `Content-Length` the same way, and arrays it allocated with `new[]` are freed with `delete[]`. Tested in `WHttp_test`, over real sockets.
- **Running other programs** (upstream): opening a URL or file (`WApp::openUrlInBrowser`, the GUI's `OpenFile`) built a shell command, `"open " + url + " &"`, so a `;` or `$(...)` in a URL or file name ran commands. The new `WApp::openFile` passes the path or URL to `open` (macOS) or `xdg-open`, then `gnome-open` (Linux), as one argument with no shell. `WApp::systemCall` no longer uses a shell either, like `systemExecute` and `systemCall` on Windows: quotes still group an argument (and are now removed, as a shell would; they used to be passed on), but pipes, redirection, `$VARIABLES`, wildcards and `;` are ordinary text. A program that can't be run exits with 127; the forked child used to throw instead and carry on as a second copy of the caller. Tested in `WApp_test`, with a fake `open` on `PATH` recording what it was given. The `depends/security` tools aren't built here; their `satellite` runs whatever commands its server sends, by design.
- **Reading numbers:** every `atoi` and `atof` is replaced by `parseNumber` (`WError.h`, beside `to_str`), built on `std::from_chars`: the whole text must be one number in range (finite, for decimals), and `.` is the decimal point whatever the locale. `atoi` and `atof` return 0 for `abc` and 12 for `12x`, and overflow silently. So now: JSON `1e5` is 100000, not 1; an ARFF value like `1.5abc` or `1.8m` is an error, not 1.5; a URL port must be 1-65535 (70000 used to become 4464); `pop_uint` rejects empty and too-big values; a category given by position must be in range; and in the `community` demo, a request for an item that doesn't exist (`?item=999999`) gets "No such item" instead of reading past the end of the list.
- **Bug fixes** (all upstream bugs; those with a visible effect have a test, in SAKBox's tests or Waffles' own suite):
  - `WBlockElPos::inverse` assigned instead of comparing (`y = UNKNOWN_REAL_VALUE ? ...`), so it always returned "unknown", and it inverted the wrong pieces of the function.
  - `WBitTable` and `WMatrix` assignment destroyed the data when assigned to themselves.
  - Integer division: sparse k-means' and `WRecommender`'s running means were wiped at every step, `WMath::wilcoxonPValue` truncated n(n+1)/4, and `WCluster` and `WRecommender` lost fractions.
  - `WArgReader::pop_double` turned non-numbers into 0; it now rejects them.
  - `WKMeansSparse` only ever recomputed the first row's cluster (a pointer into the cluster list stopped moving), and left an empty cluster empty; it's now restarted from the largest cluster's worst-fitting row. This also fixes `WSparseClusterRecommender`, whose test limit was loose enough to pass with the bug.
  - `WDenseClusterRecommender` clustered uninitialised memory for unrated items; they're now marked unknown. `WFuzzyKMeans`, which it clusters with, checked that its starting centroids differ by their squared distance being 0, which for an unknown value (-1e308) against a known one overflows; where Waffles turns floating-point exceptions on, that stopped `waffles:test` (first seen on Linux, since they weren't turned on for macOS; see below). The rows are now compared value by value.
  - `WApp::enableFloatingPointExceptions`, called by the test suite, the command-line tools and several demos, did nothing on macOS: it uses `feenableexcept`, a glibc extension macOS doesn't have, and the macOS branch was a commented-out line for Intel Macs. It now enables the traps there too (the FPCR register's trap bits on Apple silicon, the SSE control register on Intel), so an overflow, a division by zero or a NaN-producing operation stops the program on a Mac as it does on Linux, instead of carrying on with INF or NaN. On Apple silicon the signal is SIGILL ("illegal instruction"), not SIGFPE. Its comment also said it threw an exception; it raises a signal, which can't be caught.
  - A `WBaselineRecommender` loaded from a file didn't restore how many items it had, so it read an uninitialised count, and typically predicted 0 for every item. Tested in `WRecommender_test`.
  - Saved files lost precision: `WDom` wrote every number in JSON with 6 decimal places (`std::fixed`) and in XML with 6 significant digits, so a saved model came back changed (0.1234567891 as 0.123457) and any value under 0.0000005, such as a small neural-network weight, as 0. It now writes the shortest text that reads back as exactly the same number (`std::to_chars`): `0.1` stays `0.1`, `1e-9` is `1e-09`, and whole numbers keep a decimal point (`1.0`) so they load as numbers with a fraction rather than integers. Files saved before still load; files saved now are larger, since they keep every digit. Tested in `WDom_test`.
  - `WExtendedKalmanFilter` has virtual functions but its destructor wasn't virtual, so a subclass deleted through it wasn't destroyed in full. It's virtual now, which the repo's `-Wnon-virtual-dtor` requires.
  - `WMatrix::parseArff` leaked the relation it was building whenever a file failed to parse (a bad attribute, no `@data`, and so on). It's owned by a `std::unique_ptr` until the matrix takes it.
  - The ray tracer's bounding-box tree sorted objects by centre with an unstable sort, so objects whose centres tie were ordered however the standard library chose. That shapes the tree and so the pixels where objects meet at equal distances: GCC's library rendered a scene differently from macOS's. It's a stable sort now (ties keep the order objects were added in), so a scene renders the same everywhere.
  - `WSparseInstance` couldn't be reloaded once saved (missing from `WLearnerLoader`, and its loading constructor left a pointer uninitialised), mismatched rows and labels when pruning, and stepped an iterator before `begin()`.
  - `WTensor::parseArff` loaded only half of a file's values and divided by zero for a file with no attributes; its errors now name the column.
  - `WJsonAsADatabase`'s `=` crashed on a missing field with more path after it (`.a.b = 1`), replaced the whole database for a missing last field (`.a = 1`), named fields with the space before `=` (`"a "`), and mis-indexed one past a list's end; `WDomNode::set` crashed on a new, empty list.
  - `WAutoFilter` asked itself, not the learner, whether nominal values needed handling, so six of its rules never ran (one also checked labels where it meant features). No change for Waffles' own learners.
  - `WNeuralNet::clone` and `copyTopology` threw for every network: copying a layer copied its `WVecWrapper`s through `WVec`'s throwing copy constructor. The copy also left its gradient count uninitialised, so binding a clone failed with "Gradient size problem".
  - `WRayTraceTriMesh::makeCylinder` built its triangles facing inward. Upstream's dead mesh-orientation code is revived as `orientTriangles`.
  - `WImage::munge`'s "waves around the middle" effect (used by `WImage::captcha`) worked out each pixel's angle from the middle with unsigned numbers, which wrapped to about 4 billion above and left of it, so the waves came out wrong there.
  - HTTP `Date` and `Last-Modified` headers dropped the leading zero of days under 10 (`Thu, 5 Nov 2026`; HTTP wants `05`). They're made by the new `WTime::httpDate`. It and `WTime::asciiTime` no longer use `asctime`, `gmtime` or `localtime`, which share one buffer between all threads (two threads formatting a time at once could get each other's); the names are English whatever the locale, as HTTP requires.
  - `savePng` without the alpha channel (`savePng(image, file, false)`) wrote every pixel as a copy of the first: the RGB loop never moved to the next pixel. The overloads without the flag save alpha, so nothing in Waffles hit it. Tested in `WImagePng_test`, which saves and loads an image both ways.
  - `loadPng` loaded only 8-bit RGB and RGBA PNGs, and threw for the rest: the calls asking libpng to expand other kinds to RGB came after `png_read_update_info`, where libpng rejects them, so they had been commented out. They now come before it, so greyscale (with or without alpha), palette (its transparency becomes alpha), 1, 2 and 4-bit, and 16-bit PNGs (scaled to 8 bits) all load. Tested in `WImagePng_test`, which writes each kind with libpng directly.
  - SHA-512 and SHA-384 (`sha2.cpp`) gave the wrong hash for 512 MiB or more: the message length written into the last block took its high word from bit 29 of the byte count, as SHA-256 does with 32-bit words, instead of bit 61. And all three hashes cut a single call's length to 32 bits, so hashing 4 GiB + 3 bytes in one call hashed only 3. Waffles' own uses (`WCrypto`, `WDynamicPage`) hash small inputs, so they weren't affected. `sha2_test` checks both without big buffers (it sets the byte count directly, and hashes an unreadable page past a small one); 512 MiB and 4 GiB + 3 byte zero buffers were also checked once against `shasum`.
  - `plot stats` skipped a continuous column's statistics on any error, not just when all its values are missing; it now checks for that case and lets other errors through. The HTTP server said nothing when it failed to send a POST response; it now reports it, as it does for GET and HEAD.
  - A client that hung up before its reply was sent stopped the whole HTTP server: writing to its socket raised SIGPIPE, which ends the process. Sockets now send with SIGPIPE turned off (`MSG_NOSIGNAL` / `SO_NOSIGPIPE`), so the send fails with an error, the server drops that connection and carries on. Failed sends now say why: the socket code rethrew errors as a plain `std::exception` (`throw e`), which lost the message; `plot` and `wizard` did the same when their servers stopped.
  - `WStemmer` wrote the `'\0'` after a 64-letter word one byte past its buffer; words are now cut at 63 letters, as `WVocabulary` already does without a stemmer.
  - `WHttpServer::unescapeUrl` (URL parameters) took any letter after `%` as a hex digit and anything else as 2 or 0, so `%G0` decoded to `'\0'` and cut the value short, and a `%` near the end was dropped. Only `%XY` with two hex digits is decoded now; any other `%` is kept as it is.
  - `tolower` was given plain `char`s, which are negative for bytes above 127 (UTF-8 letters), and that is undefined behaviour; they are cast to `unsigned char` first.
  - Smaller fixes clang-tidy found: wrong `throw`s, `WHttp`'s port, `memcpy` of a non-trivial type, and how the `plot` and `wizard` tools seed their generators.
- **Tests:** the suite used to pass whatever failed (failures were printed, not reported) and skipped the command-line tool tests under Bazel; both are fixed. Three test functions that were never run (`WDenseClusterRecommender`, `WFunctionParser`, `WSparseInstance`) now are, with real limits instead of placeholders. `WWavelet::test` stays out: it reads a file on its author's machine.
- **Line endings:** Waffles' sources, headers and README had CRLF line endings; they're stored with LF now, like the rest of the repo (see the top-level README).
- **Static analysis:** Waffles is checked by the repo's clang-tidy setup like the rest of the repo (see the top-level README). It's formatted with clang-format in its own style rather than the repo's (`.clang-format` here: tabs, braces on their own lines, `if(` with no space, no line limit), chosen to match how most of Waffles was written so formatting changed as little as possible; `tests/` has the repo style (`tests/.clang-format`). Data tables and other hand-aligned blocks are marked `// clang-format off`. The third-party code bundled here (DirectInput's `dinput.h` and KTH's `md4` in `src/depends/security/`, Gladman's `sha2` and `uitypes.h`) is listed in the repo's `.clang-format-ignore` and keeps its own layout. Fixes clang-tidy applied itself (`override`, `nullptr`, `const &` parameters) are in. Sorts of pointers say what they sort by, with `std::ranges` projections (`std::ranges::sort(m_rows, std::ranges::less{}, [dim](const WVec* pRow) { return (*pRow)[dim]; })`) instead of one-use comparator classes. `bugprone-nondeterministic-pointer-iteration-order` flagged every `std::sort` of pointers, even ones comparing the values pointed at, as these did; it doesn't look at `std::ranges` algorithms at all, so sorting pointers by address that way would go unflagged. Their results, including the order of equal values, are pinned by `WMatrix_test`, `WRayTrace_test` and `WRegion_test`. The copied SHA-2 code (`sha2.cpp`, by Brian Gladman) added to its byte count inside `if` conditions (`if((ctx->count[0] += free) < free)`); the addition is now its own statement, rather than the lines being marked as copied code, and `sha2_test` checks the standard digests and the carry into the count's high word. The last few: `WBlock::deserialize`, the static factory that makes a block from a DOM node, is now `WBlock::deserializeBlock`, since `WNeuralNet::deserialize` (loading a net in place, like `WVec::deserialize`) hid it under the same name with a different meaning; a Poisson deviate's candidate is rounded with `lround` instead of `(int)(x + 0.5)`; `WNodeHashTable::get` reads its result as a typed pointer instead of through a `void**` cast; `WTensor`'s copy constructor calls `WVecWrapper`'s; a decision-tree node's child array is value-initialised instead of `memset`; and `WSimpleAssignment::test` checks `operator<` against an equal copy rather than `a<a`. `WNeuralNet_test`, `WRand_test` (deviates recorded before the change), `WHashTable_test` and `WVec_test` cover them. Waffles now has no clang-tidy findings.
- **SHA-2 stays Brian Gladman's copy** (`sha2.cpp`, `sha2.h`, `uitypes.h`), on purpose, rather than the registry's BoringSSL. It's about 800 lines with no dependencies, fixed (the length bugs above) and tested (`sha2_test`), and Waffles only hashes small inputs with it: `WCrypto`'s scrambling and `WDynamicPageServer::passwordSalt()`. BoringSSL is large to build, makes no promise of a stable API, and would bring in a TLS library nothing else needs. Revisit if Waffles ever needs real cryptography (TLS, signatures), when BoringSSL would come in anyway.
- **Warnings:** counters that are computed but never read (`epochs`, `hits`, `nDepth`, `nTries`, ...) are kept, as instrumentation, and marked `[[maybe_unused]]`.
- **Demos brought up to date:** upstream changed the neural network API in 2016-2019 (layers became blocks, several blocks per layer, weights in one vector) without updating every demo. `hello_ml` only needed a dead include removed. `fourier_net` was rewritten for blocks, using upstream's last version of the deleted `WNeuralNet::fourier` (2017) and the 2015 layer helpers it relied on as references; its data, deleted upstream in 2015, is restored from history.
- `WFile::loadFile` reports the missing path and the current directory when a file isn't found.

Changes inside the code are marked with `SAKBox:` comments where they fix behaviour.

## Tests

Two kinds:

- `:test` is upstream's own suite (`src/test/main.cpp`), including the command-line tool tests.
- SAKBox's tests are googletest files in `tests/`, one per area of the library and named after its header and spelled as it is (the repo-wide rule, see the top-level README): `WMatrix_test.cpp` covers `WMatrix.h`, `WRayTrace_test.cpp` covers `WRayTrace.h`, and so on. Each is its own target (`:WMatrix_test`), listed in `BUILD`. Put a new test in the file for the area it tests, adding a file (and its name to the list in `BUILD`) if there isn't one yet, rather than grouping tests by why they were written. Say why a test exists in its comment instead: the bug it caught, or that it pins down behaviour before a rewrite (some values, like `WImage_test`'s pixel fingerprint, were recorded from the code before a rewrite rather than worked out).
